# Athar Verify — تحقق من أصالة التوثيق

أداة رسمية من **متجر أثر** تتيح للعميل التحقق من أن فيديو التوثيق الميداني المرتبط بطلبه
هو النسخة الأصلية المسجلة لدى المتجر، ولم يُغيَّر أو يُستبدل.

---

## المبدأ الأساسي

> **إثبات الأصالة يقوم على مطابقة الملف مع النسخة الأصلية المسجلة لدى متجر أثر، لا على كشف
> الذكاء الاصطناعي.**

هذا المبدأ مطبَّق في الكود نفسه داخل [`src/lib/analysis/verdict.ts`](src/lib/analysis/verdict.ts):

| القاعدة | التطبيق |
| --- | --- |
| مطابقة SHA-256 حاسمة | لا يستطيع أي مؤشر — ذكاء اصطناعي، بيانات تقنية، صوت — أن يخفّض نتيجة مطابقة تامة |
| مؤشرات AI لا تُنشئ نتيجة سلبية | أقصى ما تفعله هو تعليق حالة حدّية عند «تعذر التأكد» |
| عدم المعرفة ≠ عدم المطابقة | فشل التحليل يُنتج «تعذر التأكد»، لا «لا يتطابق» |
| الصوت دليل إيجابي فقط | تشابه صوتي ضعيف لا يُلغي تطابقًا بصريًا قويًا (النسخة قد تكون صامتة أو معاد ترميزها) |
| كلمة «مزيف» ممنوعة | يوجد اختبار آلي يمنع ظهورها في أي نص يراه العميل |

---

## حالات النتيجة الأربع

| الحالة | المعنى | متى تظهر |
| --- | --- | --- |
| 🟢 **Verified Original** | الملف مطابق للنسخة الأصلية المسجلة لدى متجر أثر | بصمة SHA-256 متطابقة |
| 🟢 **Verified Content Match** | مختلف تقنيًا لكنه يتطابق بدرجة عالية مع محتوى التوثيق | تشابه المحتوى ≥ 88% (حالة ضغط واتساب) |
| 🟡 **Unable to Fully Verify** | لم نتمكن من تأكيد المطابقة بشكل كامل | تشابه بين 55% و88%، أو تعذّر التحليل |
| 🔴 **File Does Not Match** | الملف لا يتطابق مع التوثيق الأصلي لهذا الطلب | تشابه المحتوى < 55% |

### لماذا نظام مصادقة مخصص بدل Auth.js؟

المتطلب هو «Auth.js أو نظام آمن مناسب». نسخة Auth.js المتوافقة مع App Router ما زالت `beta`،
ولوحة التحكم هنا تتعامل مع توثيقات عملاء حقيقيين. فاخترنا نظامًا صريحًا ومقروءًا بالكامل:
جلسات في قاعدة البيانات لا يُخزَّن منها إلا `SHA-256` للسرّ، وكوكيز `__Host-` مع `httpOnly` و
`SameSite=Lax`، وقفل الحساب بعد ٨ محاولات فاشلة، ومقارنة كلمة مرور ثابتة الزمن حتى للحسابات
غير الموجودة. الكود في [`src/lib/auth/`](src/lib/auth/).

## التشغيل السريع

### بـ Docker (الأسهل)

```bash
cp .env.example .env

# اضبط الأسرار — الحاوية ترفض الإقلاع بالقيم الافتراضية
sed -i "s|^AUTH_SECRET=.*|AUTH_SECRET=$(openssl rand -base64 48)|" .env
sed -i "s|^IP_HASH_SALT=.*|IP_HASH_SALT=$(openssl rand -base64 24)|" .env

docker compose up -d
docker compose exec app npx prisma migrate deploy
docker compose exec app npx tsx prisma/seed.ts
```

التطبيق على <http://localhost:3000> ولوحة التحكم على `/admin/login`.

لتشغيل الطابور و worker مستقل:

```bash
echo 'REDIS_URL=redis://redis:6379' >> .env
docker compose --profile queue up -d
```

### محليًا للتطوير

يتطلب Node 20+ و PostgreSQL و **ffmpeg**:

```bash
# ffmpeg مطلوب لتحليل التشابه (مطابقة البصمة تعمل بدونه)
sudo apt-get install -y ffmpeg     # أو: brew install ffmpeg

npm install
cp .env.example .env               # ثم اضبط DATABASE_URL و AUTH_SECRET و IP_HASH_SALT

npx prisma migrate dev
npx tsx prisma/seed.ts
npm run dev
```

| الأمر | الوظيفة |
| --- | --- |
| `npm run dev` | خادم التطوير |
| `npm run build` | توليد Prisma Client + بناء الإنتاج |
| `npm start` | تشغيل نسخة الإنتاج |
| `npm run typecheck` | فحص الأنواع |
| `npm test` | تشغيل اختبارات الوحدة |
| `npm run worker` | تشغيل worker الوسائط (يتطلب `REDIS_URL`) |
| `npm run db:seed` | إنشاء حساب الإدارة وبيانات تجريبية |
| `npm run prisma:studio` | متصفح قاعدة البيانات |

بيانات الدخول بعد `seed` تأتي من `SEED_ADMIN_EMAIL` و `SEED_ADMIN_PASSWORD` في `.env`
(الافتراضي `admin@athrr-sa.com` / `ChangeMe!2026` — **غيّرها قبل النشر**).

## كيف يعمل التحقق

### ١. تسجيل البصمة

عند رفع الفيديو الأصلي من لوحة الإدارة:

1. المتصفح يطلب رابط رفع موقّعًا (`/api/admin/uploads/presign`) ويرفع الملف **مباشرة إلى
   التخزين** — لا يمر فيديو بحجم مئات الميجابايت عبر خادم التطبيق.
2. الخادم يقرأ الملف من التخزين ويحسب `SHA-256` بنفسه — لا يُوثق أبدًا بقيمة قادمة من العميل.
3. تُخزَّن البصمة مع اسم الملف وحجمه ونوعه وتاريخ الرفع ورقم الطلب ومن رفعه.
4. **البصمة لا تُعدَّل بعد التسجيل.** لا يوجد مسار في الكود يكتب على العمود `sha256` مرة ثانية،
   وإعادة المعالجة تُحدِّث البيانات التقنية فقط.

### ٢. مقارنة نسخة العميل

عند رفع العميل لنسخته:

```
SHA-256 متطابقة؟ ──نعم──► 🟢 Verified Original (درجة تحقق 100%)
        │
        لا  ← أمر طبيعي بعد واتساب أو تيليجرام أو إعادة الحفظ
        ▼
   تحليل التشابه
   ├─ استخراج الإطارات (64 عيّنة) وحساب بصمة إدراكية pHash لكل إطار
   ├─ محاذاة زمنية بين التسلسلين  →  sequence score
   ├─ تغطية الإطارات (غير حساسة للترتيب)  →  coverage score
   ├─ نسبة الإطارات المتطابقة ضمن عتبة pHash
   ├─ بصمة صوتية (sub-band) ومقارنة المدة
   └─ AI Media Analysis (إشارات مساعدة فقط)
        ▼
   محرّك القرار  →  إحدى الحالات الأربع + درجة ثقة مُفسَّرة
```

الملف الذي يرفعه العميل **يُحذف فور انتهاء الفحص** — يُحتفظ بالتقرير فقط.

### ٣. أرقام مقيسة

من اختبار فعلي على مقطع 12 ثانية بدقة 640×360 (`npm test` يغطي المنطق نفسه):

| الحالة | النتيجة | التشابه | درجة الثقة |
| --- | --- | --- | --- |
| الملف نفسه | 🟢 Verified Original | — | 100% |
| إعادة ترميز 320×180 CRF 34 (حالة واتساب) | 🟢 Verified Content Match | 95.2% (64/64 إطار) | 96.1% |
| إعادة ترميز عنيفة 240×136 CRF 40 بلا صوت | 🟢 Verified Content Match | 95.0% (64/64 إطار) | 95.0% |
| مقطع مقصوص (6 ثوانٍ من المنتصف) | 🟢 Verified Content Match | 99.0% (32/32 إطار، إزاحة 3 ثوانٍ) | 79.2% |
| فيديو مختلف تمامًا | 🔴 File Does Not Match | 31.5% (0/64 إطار) | 76.6% |

### شبكة أخذ العيّنات المشتركة

عند فحص نسخة العميل، تُؤخذ عيّنات إطاراتها **بنفس معدل العيّنات الذي عولج به الملف الأصلي**
(محفوظ في `metadata_json.frameSampling`) لا بالقيمة الحالية لـ `FRAME_SAMPLE_COUNT`. بهذا تقع
الإطارات على شبكة زمنية واحدة، فيظهر القص كإزاحة على تلك الشبكة بدل أن تتداخل الشبكتان.

الأثر مقيس: قبل هذا الربط كان المقطع المقصوص يسجّل 69% ونسخة واتساب 64% (لأن الأصل كان معالجًا
بـ 32 عيّنة والنسخة تُؤخذ بـ 64)؛ بعده صارا 99% و95% على الترتيب. كما يعني ذلك أن تغيير
`FRAME_SAMPLE_COUNT` لا يُبطل التوثيقات المعالَجة سابقًا — وإن أردت الاستفادة من كثافة أعلى
استخدم زر **إعادة المعالجة** في لوحة التحكم.

## AI Media Analysis

وحدة مستقلة في [`src/lib/analysis/ai/`](src/lib/analysis/ai/) خلف واجهة `AiAnalysisProvider`،
لتوصيل مزود تجاري لاحقًا دون تعديل بقية النظام.

| المزود | `AI_ANALYSIS_PROVIDER` | الوصف |
| --- | --- | --- |
| `HeuristicAiProvider` | `heuristic` (افتراضي) | تحليل محلي مجاني: اتساق التسلسل الزمني، الإطارات المكررة، كثافة الانتقالات، تباين الإضاءة، بيانات الالتقاط، أداة الترميز، شذوذ معدل الإطارات، ديناميكية الصوت |
| `HttpAiProvider` | `http` | محوّل لواجهة خارجية مدفوعة. يرسل **الإشارات المستخرجة فقط** لا الفيديو نفسه |
| `MockAiProvider` | `mock` | مزود تجريبي يعلن عن نفسه أنه غير حقيقي |

النتيجة تُعرض دائمًا بإحدى ثلاث صياغات ثابتة، مُعرَّفة في مكان واحد لمنع أي مزود مستقبلي من
المبالغة:

- «لم تظهر مؤشرات قوية على التوليد الاصطناعي أو التلاعب في هذا الملف.»
- «ظهرت بعض المؤشرات التي تستحق المراجعة. هذه المؤشرات ليست إثباتًا على التوليد الاصطناعي.»
- «لم يكتمل تحليل مؤشرات الذكاء الاصطناعي لهذا الملف، لذلك لا يمكن الاعتماد على نتيجته.»

> **تنويه:** تحليل مؤشرات الذكاء الاصطناعي هو أداة مساعدة ولا يمثل إثباتًا قطعيًا بمفرده.
> يعتمد نظام أثر للتحقق بشكل أساسي على مطابقة الملفات مع التوثيقات الأصلية المسجلة لدينا.

لإضافة مزود جديد: نفّذ `AiAnalysisProvider` وسجّله في `aiProvider()`.

### تحليل الصوت والتوسعة المستقبلية

[`src/lib/media/audio.ts`](src/lib/media/audio.ts) يفكّ الترميز إلى PCM أحادي 8 kHz ويستخرج
بصمة sub-band بأسلوب Haitsma–Kalker مع FFT مكتوب في المشروع، إضافة إلى إحصاءات الموجة
(RMS، الذروة، معامل القمة، نسبة الاقتطاع، نسبة الصمت، معدل عبور الصفر). البنية جاهزة لإضافة
Audio Deepfake Detection لاحقًا: يستهلك المكشوف نفسه من PCM ويضيف إشارات إلى التقرير.

## الخصوصية والأمان

| الإجراء | التفاصيل |
| --- | --- |
| رابط بسرّ | `/v/ATH-XXXXXXXX?t=<token>` — الرقم وحده لا يكفي، والمقارنة تتم على `SHA-256` للسرّ بزمن شبه ثابت |
| قائمة سماح للحقول | كل حقل يراه العميل يمر عبر [`presenters.ts`](src/lib/services/presenters.ts). إضافة عمود جديد لا يظهر للعميل ما لم يُضَف صراحةً |
| لا بيانات حساسة | رقم جوال العميل والعنوان لا يُعرضان أبدًا. اسم العميل لا يظهر إلا بتفعيل `showCustomerName` |
| حدود الطلبات | بحث: ١٠/دقيقة + سقف يومي يمنع تخمين أرقام الطلبات · رفع: ١٢/ساعة · دخول: ٨/١٥ دقيقة |
| تخزين خاص | لا يُنشر أي كائن للعموم. كل قراءة تمر عبر `/api/media/...` بعد التحقق من الرمز |
| تجزئة IP | لا يُكتب عنوان IP خام في قاعدة البيانات ولا في السجلات — تُخزَّن تجزئة مملَّحة فقط |
| تذاكر الرفع | رابط الرفع الموقّع يُرافقه HMAC يربط المفتاح بالمشرف الذي طلبه، فلا يمكن تسجيل أي كائن آخر في التخزين كتوثيق |
| حذف ناعم | حذف الطلب يُعطّل الرابط العام ويُخفيه عن العملاء، مع الاحتفاظ بالبصمات وسجل التحقق للمراجعة |
| سجل تدقيق | كل عملية إدارية تُسجَّل في `audit_log` |
| حماية الإقلاع | التطبيق يرفض العمل في الإنتاج بأسرار افتراضية |
| منع الأرشفة | صفحات التحقق تحمل `noindex` |

عند التشغيل خلف بروكسي عكسي، اضبط `TRUSTED_PROXY_HOPS` ليُقرأ عنوان العميل من الموضع الصحيح
في `X-Forwarded-For`.

## التخزين

الواجهة معرَّفة في [`src/lib/storage/types.ts`](src/lib/storage/types.ts):

```bash
# Cloudflare R2
STORAGE_DRIVER=r2
S3_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com

# Supabase Storage
STORAGE_DRIVER=supabase
S3_ENDPOINT=https://<project-ref>.supabase.co/storage/v1/s3

# AWS S3
STORAGE_DRIVER=s3
S3_REGION=me-south-1
S3_ENDPOINT=            # اتركه فارغًا
```

سائق `local` للتطوير أو للنشر على خادم واحد بمجلد دائم؛ لا يدعم روابط الرفع الموقّعة، لذلك
يوجّه الرفع إلى `/api/admin/uploads/direct` المحمي بالجلسة.

## المعالجة في الخلفية

| الوضع | المتطلب | السلوك |
| --- | --- | --- |
| `inline` | لا شيء | تُنفَّذ المهام داخل عملية الويب بعد إرجاع الاستجابة |
| `redis` | `REDIS_URL` | تُسلَّم المهام إلى BullMQ ويعالجها worker مستقل مع إعادة محاولة تصاعدية |

المهام: حساب البصمة · استخراج البيانات التقنية · توليد الصورة المصغّرة · استخراج الإطارات ·
تحليل التشابه · تحليل مؤشرات AI. تظهر الحالة `Processing` ثم `Verified`.

الوضع `inline` صالح للإنتاج على خادم واحد؛ الفرق أنه لا يوجد ضمان بإعادة التنفيذ إذا سقطت
العملية أثناء المعالجة — وعندها يبقى السجل ظاهرًا بحالة `PENDING` ويمكن إعادة معالجته من لوحة
التحكم.

## الاختبارات

```bash
npm test
```

٤٠ اختبارًا تغطي المنطق الذي يحدِّد النتيجة:

- **pHash** — الثبات، عدم التأثر بتغير السطوع، تحمّل ضوضاء الضغط (منمذجة كما تحدث فعلًا:
  ضوضاء على الدقة الكاملة ثم تصغير)، الفصل بين الصور المختلفة، والثبات على الإطارات المسطّحة.
- **تشابه الفيديو** — التطابق التام، النسخة المعاد ضغطها، المقطع المقصوص المُعاد أخذ عيّناته
  بمعدل مختلف، رفض المحتوى غير المرتبط.
- **محرّك القرار** — أسبقية مطابقة البصمة، أن الصوت الضعيف أو الغائب لا يُلغي تطابقًا بصريًا،
  السقوط الآمن إلى «تعذر التأكد»، ومنع كلمة «مزيف» في كل النصوص.
- **البصمة الصوتية** — المطابقة، المحاذاة على مقتطف، وإرجاع `null` بدل صفر للصوت غير المرتبط.
- **أدوات مساعدة** — تطبيع أرقام الطلبات (بما فيها الأرقام العربية-الهندية وعلامات الاتجاه
  القادمة من واتساب) وتنقية أسماء الملفات.

| `admins` · `admin_sessions` | حسابات الإدارة وجلساتها |
| `audit_log` | سجل تدقيق للعمليات الإدارية |
| `rate_limit_buckets` | حدود الطلبات عند عدم توفر Redis |

## التكامل المستقبلي مع أداة استرجاع التوثيق

النظام مبني ليُدمج مع أداة استرجاع توثيق متجر أثر برقم الطلب. نقطة الدمج جاهزة:
`loadOrderView(orderNumber)` في [`src/lib/services/verification.ts`](src/lib/services/verification.ts)
تُرجع بيانات الطلب والفيديو والصور وحالة التحقق ورابط QR وزر التحميل ورابط مشاركة واتساب في
شكل واحد `PublicOrderView`، ومكوّن `<OrderResult />` يعرضها كاملة. صفحة الطلب الموحّدة
مستقبلًا تستهلك الاثنين كما هما.
